# Вимоги до системи управління бібліотекою

## Призначення та межі

Система веде облік читачів, книг, авторів, видачі та повернення книг. Основний користувач — бібліотекар; читач зацікавлений у правильному обліку своїх позик.

Один запис BOOK представляє одну книгу для видачі. Окремий облік примірників одного видання, штрафи, бронювання та облік працівників не входять до роботи.

## Вимоги бібліотекаря та операції

| № | Вимога |
| --- | --- |
| F1 | Реєструвати читачів, переглядати та редагувати їхні дані |
| F2 | Додавати, переглядати та редагувати книги й авторів |
| F3 | Указувати одного або кількох авторів книги через BOOK_AUTHOR |
| F4 | Шукати книги за назвою, ISBN або автором |
| F5 | Перевіряти доступність книги перед видачею |
| F6 | Оформлювати позику зареєстрованому читачу із датою видачі та строком повернення |
| F7 | Фіксувати фактичну дату повернення у LOAN.return_date |
| F8 | Переглядати історію позик читача та книги |
| F9 | Показувати незавершені позики, строк повернення яких минув |

## Дані системи

| Сутність | Дані |
| --- | --- |
| MEMBER | member_id (PK), first_name, last_name, email, phone |
| BOOK | book_id (PK), title, isbn, publication_year |
| AUTHOR | author_id (PK), first_name, last_name |
| LOAN | loan_id (PK), member_id (FK), book_id (FK), loan_date, due_date, return_date |
| BOOK_AUTHOR | book_id (PK, FK), author_id (PK, FK); спільний складений PK |

## Бізнес-правила та обмеження

| № | Правило |
| --- | --- |
| B1 | Усі PK обов’язкові та унікальні; у BOOK_AUTHOR унікальною є пара (book_id, author_id) |
| B2 | Кожна позика має рівно одного наявного читача і рівно одну наявну книгу |
| B3 | Читач та книга можуть не мати позик; за весь час кожен може мати багато позик |
| B4 | Книга має не більше однієї незавершеної позики одночасно |
| B5 | Незавершена позика має порожню return_date; книга доступна, якщо таких позик немає |
| B6 | loan_date та due_date обов’язкові; due_date ≥ loan_date |
| B7 | return_date необов’язкова; після заповнення return_date ≥ loan_date |
| B8 | Повернення після due_date допустиме. Незавершена позика прострочена, якщо due_date < поточна дата |
| B9 | Кожна книга має щонайменше одного автора; автор може існувати без пов’язаних книг |
| B10 | Кожен запис BOOK_AUTHOR посилається рівно на одну наявну книгу і одного наявного автора |
| B11 | Повторення тієї самої пари книги й автора заборонено |
| B12 | Видалення читача або книги з позиками та автора з пов’язаними книгами заборонено |
| B13 | first_name та last_name у MEMBER і AUTHOR, а також BOOK.title обов’язкові й непорожні |
| B14 | email та phone необов’язкові; якщо задані, перевіряється їхній формат. Унікальність контактів не вимагається |
| B15 | isbn необов’язковий і не є PK; якщо заданий, повинен мати коректний формат ISBN-10 або ISBN-13. Унікальність ISBN не вимагається |
| B16 | publication_year необов’язковий; якщо заданий, повинен бути додатним цілим числом |

Строк позики бібліотекар задає у due_date. Фіксований строк та максимальна кількість позик читача в цій моделі не встановлюються.

## Вимоги до зручності та цілісності

- Пошук, оформлення видачі та повернення мають бути зрозумілими бібліотекарю.
- Некоректні дати, порожні обов’язкові поля та відсутні пов’язані записи мають відхилятися з поясненням.
- Повернення завершує позику, але не видаляє її з історії.
- Коли дві видачі однієї книги оформлюються одночасно, система повинна дозволити лише одну з них.

## Зв’язки

- MEMBER 1:N LOAN: читач має 0..N позик, позика має одного читача.
- BOOK 1:N LOAN: книга має 0..N позик за весь час, позика має одну книгу.
- BOOK 1:N BOOK_AUTHOR: книга має 1..N записів авторства.
- AUTHOR 1:N BOOK_AUTHOR: автор має 0..N записів авторства.
- BOOK M:N AUTHOR реалізовано через BOOK_AUTHOR.

Діаграма показує структуру та кардинальність. Правила щодо дат, форматів і одночасних позик доповнюють її текстом; SQL у лабораторній №1 не створюється.
