# Підготовка до захисту

**Що таке DDL?** Команди визначення структури бази. CREATE TABLE створює таблицю зі стовпцями, типами й обмеженнями. CREATE INDEX створює індекс. INSERT належить до роботи з даними, а не до DDL.

**Чому п'ять таблиць?** Це п'ять сутностей lab1: читач, автор, книга, позика та авторство книги. Нової предметної області немає.

**PRIMARY KEY?** Значення, яке однозначно визначає рядок. Воно унікальне й не може бути NULL. У book_author ключ — пара book_id та author_id. Кожен компонент окремо може повторюватися.

**FOREIGN KEY?** Перевіряє, що пов'язаний запис існує. Наприклад, loan.member_id має вказувати на member.member_id. Спочатку додаємо читача, потім його позику.

**NOT NULL?** Не дозволяє невідоме значення. Але порожній рядок — це не NULL, тому для імен використано ще CHECK із btrim.

**UNIQUE?** Забороняє повторення значень. PK уже включає унікальність. Контакти та ISBN не унікальні за вимогами lab1. Частковий унікальний індекс перевіряє book_id тільки серед позик, де return_date IS NULL.

**CHECK?** Перевіряє правило для рядка: due_date >= loan_date. Повернення після строку дозволене. CHECK пропускає NULL, тому return_date може бути невідомою; обов'язкові поля захищає NOT NULL.

**DEFAULT?** Значення при пропуску стовпця в INSERT. Тут дати задає бібліотекар, тому довільний строк за замовчуванням не встановлено.

**INSERT INTO?** Додає рядки. Ми явно перелічуємо стовпці, а далі значення VALUES. Батьківські таблиці заповнюються раніше дочірніх.

**Чому ISBN і телефон — рядки?** У них можуть бути початкові нулі, X або +. Обчислювати їх як числа не потрібно. ISBN перевіряється за форматом без дефісів, не за контрольною сумою.

**Як працює M:N?** Книга може мати багатьох авторів, а автор — багато книг. Кожен рядок book_author з'єднує одну книгу й одного автора. Пари (4,4), (4,5), (2,2), (5,2) показують обидві сторони цього зв'язку.

**Навіщо loan?** Кожна видача — окремий запис. Тому книга й читач мають багато позик за весь час. Історія зберігається після заповнення return_date. Зв'язків 1:1 тут немає.

**Що заважає видати книгу двічі?** Унікальний індекс loan_one_open_per_book не дозволить два рядки з тим самим book_id та NULL у return_date. Після повернення рядок перестає входити до цього індексу.

**Чи гарантує FK хоча б одного автора в кожної книги?** Ні. FK перевіряє наявність книги для авторства, а не авторства для книги. Потрібен контроль операції: додати книгу й авторство разом, перевірити запит «книги без авторів» перед COMMIT. DDL цієї роботи не забезпечує це правило автоматично; це прямо зазначено у звіті.

**Навіщо BEGIN, COMMIT, ROLLBACK?** BEGIN починає транзакцію, COMMIT зберігає весь набір змін, ROLLBACK скасовує його. Негативні тести відкочуються, щоб не змінити приклад даних.

**Як перевірити в pgAdmin?** Створити порожню базу, відкрити Query Tool, виконати schema.sql, data.sql і SELECT із queries.sql. Очікуються 5/5/5/6/5 рядків. Потім окремо виконати блоки constraint-tests.sql; неправильні дані повинні викликати зазначені помилки. Після кожного блоку виконати ROLLBACK.
