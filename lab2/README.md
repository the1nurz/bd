# Лабораторна робота №2

**Тема:** Перетворення ER-діаграми на схему PostgreSQL.

## Мета та предметна область

Перетворити ER-модель бібліотеки з [лабораторної №1](../lab1/README.md) на таблиці PostgreSQL, задати ключі й обмеження та підготувати тестові дані. Бібліотека веде облік читачів, книг, авторів та позик. Один запис book представляє одну книгу для видачі; окремих примірників, штрафів і бронювань немає.

Джерело завдання: [офіційний lab_2.md](https://github.com/ZheniaTrochun/db-intro-course/blob/master/labs/2%20-%20DDL/lab_2.md), переглянуто 25.10.2026. Згаданих у запиті PDF/DOCX серед доступних вкладень не було. Використано офіційний Markdown із репозиторію викладача.

## Таблиці та зв'язки

| Таблиця | Призначення | PK | FK |
| --- | --- | --- | --- |
| member | Читачі | member_id | — |
| author | Автори | author_id | — |
| book | Книги | book_id | — |
| book_author | Авторство M:N | (book_id, author_id) | book_id → book, author_id → author |
| loan | Позики | loan_id | member_id → member, book_id → book |

Читач і книга мають 0..N позик. Кожна позика має одного читача й одну книгу. M:N між книгами й авторами реалізовано через book_author. Зв'язків 1:1 у lab1 немає. Атрибути й предметну область збережено; використано малі літери для SQL-ідентифікаторів.

## Запуск у Windows через pgAdmin 4

1. Якщо PostgreSQL відсутній, установіть його разом із pgAdmin 4. Запустіть сервер та підключіться в pgAdmin, використовуючи власні ім'я користувача і пароль.
2. У дереві сервера натисніть **Databases → Create → Database**, назвіть нову порожню базу `library_lab2`.
3. Натисніть на цю базу правою кнопкою та відкрийте **Query Tool**. Увімкніть Auto-commit.
4. Через **Open File** відкрийте `schema.sql`, виконайте весь файл (F5). Переконайтеся, що в Messages немає ERROR і транзакція завершилася COMMIT.
5. Так само виконайте `data.sql`, потім `queries.sql`. Виконуйте SELECT по одному, щоб переглянути кожен результат у Data Output.
6. У дереві **Schemas → public → Tables** натисніть Refresh. Має бути п'ять таблиць. Запити підрахунку повинні дати 5 читачів, 5 авторів, 5 книг, 6 пар авторства і 5 позик.
7. Виконайте блоки `constraint-tests.sql` по одному за інструкцією нижче. Збережіть власні результати або скриншоти для здачі.

Скрипти призначені для першого запуску в порожній базі. Повторний запуск не видаляє даних і може дати помилку дублювання. Для повторення створіть іншу порожню базу. Якщо виникла помилка всередині BEGIN, виконайте `ROLLBACK;`, виправте причину й повторіть відповідний файл.

### Альтернатива: psql у PowerShell

Якщо psql відсутній у PATH, використайте повний шлях до `psql.exe` у каталозі bin вашої версії PostgreSQL. Виконуйте з кореня репозиторію bd:

```powershell
psql -h localhost -U postgres -d library_lab2 -v ON_ERROR_STOP=1 -f .\lab2\schema.sql
psql -h localhost -U postgres -d library_lab2 -v ON_ERROR_STOP=1 -f .\lab2\data.sql
psql -h localhost -U postgres -d library_lab2 -v ON_ERROR_STOP=1 -f .\lab2\queries.sql
```

Пароль вводиться на запит клієнта. Не зберігайте його у Git.

## Як перевіряти обмеження

`constraint-tests.sql` містить навмисно некоректні запити. У pgAdmin виділяйте один блок від BEGIN до INSERT/DELETE, запускайте його, звіряйте код помилки з коментарем, потім окремо виконуйте ROLLBACK. Не запускайте весь файл як одну звичайну перевірку: очікувана помилка може зупинити виконання до ROLLBACK. Останній позитивний блок має виконатися без помилок і також відкочується. Після тестів повторіть підрахунок рядків.

Перевіряються PK, складений PK, усі чотири FK, NOT NULL, дати, формати контактів та ISBN, додатний рік, непорожнє ім'я, заборона двох відкритих позик і видалення пов'язаних даних. Частковий UNIQUE INDEX зберігає правило про одну відкриту позику навіть за конкурентних INSERT.

## Припущення та межі

- Ключі INTEGER задаються явно для простоти прикладів; автоматична генерація не потрібна завданню.
- Контакти та ISBN не унікальні: lab1 цього прямо не вимагає. UNIQUE забезпечується первинними ключами та частковим індексом. Окреме обмеження UNIQUE на контакти змінило б правила lab1.
- ISBN записується без дефісів: 10 символів (останній може бути X) або 13 цифр. Перевіряється формат, не контрольна сума. Телефон: необов'язковий + і 7–15 цифр; email перевіряється спрощено. Це домовленості про формат введення.
- DEFAULT не встановлено: дати видачі й строк повернення задає бібліотекар, а NULL для необов'язкових полів і так є стандартною поведінкою.
- B9 «кожна книга має хоча б одного автора» не забезпечується звичайними FK/NOT NULL: вони перевіряють дочірній запис, але не його наявність у кожного батька. Книгу та авторство потрібно додавати разом у транзакції; перед COMMIT перевіряти відсутність книг без авторів запитом з queries.sql. Також перевіряйте видалення останнього авторства. Це контроль операції, а не автоматична гарантія DDL; у довільних SQL-сеансах правило можна порушити. Тригери та додаткові атрибути не вводилися, щоб зберегти модель і рівень складності. У початкових даних автор є в кожної книги.
- Перевірки дат не забороняють перетини вже завершених історичних позик: такого окремого обмеження в lab1 не визначено.
