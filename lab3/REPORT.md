# Звіт до лабораторної роботи №3

**Тема:** Маніпулювання даними SQL (OLTP).
**Мета:** виконати вибірку, додавання, зміну й видалення окремих записів бібліотеки та перевірити результати у PostgreSQL.

## Завдання та предметна область

Прочитано всі три версії завдання викладача: [Markdown](https://github.com/ZheniaTrochun/db-intro-course/blob/master/labs/3%20-%20OLTP/lab_3.md), [PDF](https://github.com/ZheniaTrochun/db-intro-course/blob/master/labs/3%20-%20OLTP/Lab%203%20SQL%20Data%20Manipulation%20OLTP%20uk.pdf) та [DOCX](https://github.com/ZheniaTrochun/db-intro-course/blob/master/labs/3%20-%20OLTP/Lab%203%20SQL%20Data%20Manipulation%20OLTP%20uk.docx). Також опрацьовано пов'язану лекцію про DML. Матеріали переглянуто 25.11.2026, коміт джерела `fcbed425a9f1470751ce84dd850e9a7b230f24ee`.

Markdown вимагає описати виконані запити, PDF/DOCX додатково зазначають підсумок схеми. У звіті наведено обидва описи. Окремого номера варіанта немає: за `lab1` і `lab2` продовжено систему управління бібліотекою. Каталог `KR` стосується іншої роботи.

## Схема бази даних

| Таблиця | Стовпці | Ключі |
| --- | --- | --- |
| member | member_id, first_name, last_name, email, phone | PK member_id |
| author | author_id, first_name, last_name | PK author_id |
| book | book_id, title, isbn, publication_year | PK book_id |
| book_author | book_id, author_id | PK (book_id, author_id); FK до book та author |
| loan | loan_id, member_id, book_id, loan_date, due_date, return_date | PK loan_id; FK до member та book |

Один запис `book` — одна книга для видачі. `book_author` реалізує зв'язок M:N між книгами й авторами. `return_date IS NULL` означає відкриту позику. Історія залишається після повернення книги.

Схема з `lab2` забезпечує PK, FK, обов'язкові поля, непорожні імена й назви, формати контактів та ISBN, додатний рік і коректний порядок дат. Частковий індекс `loan_one_open_per_book` забороняє дві відкриті позики однієї книги. `ON DELETE RESTRICT` зберігає пов'язані дані. ISBN необов'язковий і неунікальний; перевіряється формат, а не контрольна сума.

Кожна початкова книга має автора. Загальна автоматична гарантія цього правила відсутня в `lab2`: FK перевіряє наявність батьківського запису, але не зобов'язує книгу мати рядок у `book_author`. У цій роботі авторство додається в одній транзакції з книгою, а видаляється разом із навчальною книгою. Схему попередньої роботи не змінено.

## Операції зі зміною даних

| Операція | Мета та очікуваний результат | Фактичний результат |
| --- | --- | --- |
| D1 | Зареєструвати читача 1001 | PASS: додано Дмитра Савчука; SELECT повернув 1 рядок |
| D2 | Додати навчального автора 1001 | PASS: додано 1 рядок; дані підтверджено SELECT |
| D3 | Додати книгу 1001 та її авторство | PASS: по 1 рядку у book і book_author; обидві вставки перевірено SELECT |
| D4 | Перевірити доступність книги 5 та видати її читачу 1001 | PASS: книга доступна; створено позику 1001 від 25.11.2026 до 09.12.2026 |
| D5 | Змінити email і телефон читача 1001 | PASS: змінено 1 рядок; dmytro.new@example.com та +380671112233 |
| D6 | Уточнити рік навчальної книги | PASS: 1 рядок, рік змінено з 2025 на 2026 |
| D7 | Продовжити строк відкритої позики 1001 | PASS: 1 рядок, due_date змінено з 09.12.2026 на 16.12.2026 |
| D8 | Повернути книгу та зберегти позику в історії | PASS: return_date = 26.11.2026; позика існує, книга 5 знову доступна |
| D9 | Видалити авторство навчальної книги перед видаленням самої книги | PASS: видалено 1 рядок, наступний SELECT порожній |
| D10 | Видалити навчальну книгу без позик і авторства | PASS: видалено 1 рядок, наступний SELECT порожній |
| D11 | Видалити навчального автора без книг | PASS: видалено 1 рядок, наступний SELECT порожній |

Кожний `INSERT` має список стовпців і наступний контрольний `SELECT`. Перед кожним `UPDATE` та `DELETE` показано записи з тим самим `WHERE`, після операції — результат. Усього виконано 5 `INSERT`, 4 `UPDATE`, 3 `DELETE`. Кожна зміна зачепила один потрібний рядок.

Демонстрація виконується від `BEGIN` до `ROLLBACK`, тому початкові дані зберігаються. Це навчальна послідовність коротких операцій бібліотекаря; у звичайній роботі завершену бізнес-операцію зберігають через `COMMIT`. Дати фіксовані для повторюваності, ID 1001–1002 призначені для демонстрації.

## Фактичне тестування

Перевірку виконано 25.11.2026 у PostgreSQL 18.6, x86_64-windows, через `psql` з `-X` і `ON_ERROR_STOP=1`. Використано ізольований локальний кластер `127.0.0.1:55433`, користувача `lab3` та базу `library_lab3`. Наявні бази користувача не змінювалися. Ручне виконання в pgAdmin у цьому сеансі не проводилося.

`setup.sql`, `queries.sql` та `oltp.sql` виконалися успішно. Додаткова перевірка через Python зі стандартної бібліотеки запускала фактичні SQL-файли через psql: звірено кількості й ID результатів Q1–Q8, усі 18 непорожніх рядків контрольних SELECT в D1–D11 та кількості змінених рядків. Після `ROLLBACK` порівняно всі рядки й усі стовпці п'яти таблиць із початковим станом — змін немає. Python для запуску лабораторної не потрібен.

| Тест у tests.sql | Очікування | Фактичний результат |
| --- | --- | --- |
| T1 | Кількості 5/5/5/6/5, жодної книги без автора | PASS |
| T2 | Заборонити другу відкриту позику книги 1 | PASS, SQLSTATE 23505 |
| T3 | Заборонити позику невідомому читачу | PASS, SQLSTATE 23503 |

Під час перевірки виправлено обробку очікуваної помилки T6: на цьому сервері `RESTRICT` повернув 23001. Тест також перехоплює 23503 для відповідного повідомлення FK в інших версіях. Після виправлення весь `tests.sql` завершився без помилок. Очікувані відмови обробляються окремими блоками `EXCEPTION`; якщо некоректний запит раптом пройде, тест викличе помилку. Наприкінці виконується `ROLLBACK`.
