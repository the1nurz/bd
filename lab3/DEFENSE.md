# Підготовка до захисту

**Що таке OLTP?** Обробка повсякденних коротких операцій із даними. Для бібліотеки це реєстрація читача, видача й повернення книги, зміна контактів. OLAP використовують для аналітичних підсумків.

**Яку базу використано?** Бібліотеку з попередніх лабораторних: member, author, book, book_author та loan. Схема й початкові дані підключаються з lab2, тому їх не потрібно дублювати.

**Що робить SELECT?** Читає потрібні стовпці. WHERE відбирає рядки, ORDER BY задає порядок. ILIKE шукає за шаблоном без урахування регістру, JOIN поєднує пов'язані таблиці.

**Як працює M:N?** Таблиця book_author зберігає пари книги й автора. Для пошуку книг Івана Франка поєднуються book, book_author та author.

**Як перевіряється доступність?** Книга доступна, коли NOT EXISTS не знаходить її позику з return_date IS NULL. Це читається як «не існує відкритої позики цієї книги».

**Чи достатньо SELECT перед видачею?** Він показує поточний стан. Від двох одночасних видач захищає частковий унікальний індекс loan_one_open_per_book із lab2. Два сеанси окремо не тестувалися; перевірено послідовну спробу другої видачі.

**Навіщо список стовпців у INSERT?** Щоб було зрозуміло, до яких полів належать значення. Спочатку додаються батьківські записи, потім записи з FK.

**Навіщо WHERE в UPDATE і DELETE?** Щоб змінити або видалити потрібний запис. Без WHERE операція зачепить усі рядки. Перед зміною виконано SELECT з тією самою умовою, а після — перевірку результату.

**Як повертається книга?** UPDATE заповнює return_date. Запис loan залишається в історії, а книга стає доступною. IS NULL перевіряє відсутність значення; порівняння = NULL для цього не підходить.

**Чому авторство видаляється раніше книги?** book_author посилається на book через FK. Спочатку видаляється залежний запис. У прикладі видаляються лише навчальна книга без позик і її автор; історичні позики не видаляються.

**Навіщо BEGIN і ROLLBACK?** BEGIN починає транзакцію, ROLLBACK скасовує всі її зміни. Завдяки цьому демонстрацію можна повторити. COMMIT зберіг би зміни. У lab2 схема й початкові дані вже зберігаються через COMMIT.

**Як забезпечено автора кожній книзі?** У цій послідовності книга та авторство додаються разом, а видаляються разом. Загальної автоматичної гарантії в успадкованій схемі немає; звичайного FK для неї недостатньо.

**Що перевірено фактично?** Запуск у PostgreSQL 18.6 через psql: Q1–Q8, 5 вставок, 4 оновлення, 3 видалення, повне відновлення даних після ROLLBACK та T1–T6. Повторна відкрита позика дає 23505, невідомий читач — 23503, некоректні дати — 23514, видалення читача з позиками на цьому сервері — 23001.

**Чому дати фіксовані?** Це навчальні приклади, які мають повторюватися з однаковим результатом. Q8 знаходить прострочення на 25.11.2026; для поточної дати можна використати CURRENT_DATE.
